# Slot Key UI 의사결정 기록 및 전체 화면 적용 기준

작성일: 2026-09-18
작업 브랜치: `refactor/main-page`
실제 프로젝트: `/Users/admin/Desktop/NBE12-14-2-OVENGERS`

이 문서는 메인페이지를 만들며 사용자와 합의한 판단, 이후 수정 이유, 나머지 화면에 적용할 기준을 하나로 정리한 문서다. 이전 제안과 최종 결정을 구분하며, 미래 기능에 관한 문구를 구현 사실로 해석하지 않는다.

## 1. 서비스의 인상과 의사결정 기준

- 최우선은 쾌적함이다. 들어가서 일하고 싶은 공간, 유능한 사람들이 이용할 것 같은 차분함과 신뢰감을 지향한다.
- 장식보다 실제 공간과 이용 정보를 통해 신뢰를 만든다. 가짜 리뷰, 인증, 이용자 수, 가격 또는 가용 상태를 만들지 않는다.
- 사용자 의견을 무조건 수용하기보다 목적과 가독성, 행동의 명료함을 기준으로 판단한다.
- ‘스티브 잡스 기준’은 특정 인물의 취향을 단정하는 말이 아니라 집중·절제·디테일의 완성도를 추구하는 기준이다.
- 설명은 사용자가 해당 정보를 필요로 하는 시점에 보여준다. 메인은 탐색, 상세는 선택, 결제는 금액과 조건 확인이 중심이다.

## 3. 색상

| 역할 | 결정 |
| --- | --- |
| 기본 배경 | 은은한 블루 `#F1F6FB` |
| 카드·입력창·모달 | 흰색 `#FFFFFF` |
| 주요 글자 | 잉크 네이비 `#20334D` |
| 보조 글자 | 읽을 수 있는 슬레이트 블루 `#536B85` |
| 행동·선택 강조 | 파랑 `#2864DC` |
| 경계선 | 옅은 블루 그레이 `#D7E3EF` |
| 메인 하단 마감 | 잉크 블루 `#142D4E` |

초기의 전면 다크 화면은 침침하고 기술 설명 중심이었다. 완전 흰색 시안은 밝았지만 원하는 색감이 부족했다. 따라서 밝은 블루를 기본으로 채택했다. 야경과 하단 블록만 짙은 색을 사용한다. 성공·오류·비활성은 글자와 색으로 함께 구분한다.

## 4. 타이포그래피

- 무겁고 촘촘한 제목을 피한다. 제목은 400, 작은 제목과 버튼은 500, 금액 등 필요한 강조만 600을 사용한다.
- 얇기만 한 서체도 피한다. 작은 글씨의 가독성이 중요하며, 글자 크기로 위계를 만든다.
- 현재 구현은 `Apple SD Gothic Neo`, `Noto Sans KR`, 시스템 sans-serif 폴백이다. 폰트 파일을 별도 번들한 것은 아니다.
- 생성 이미지 속 글자는 실제 폰트를 적용한 결과가 아니다. 이미지와 코드의 조판은 별도로 판단한다.
- 본문은 일반 화면 16–18px, 메인 스토리는 20–23px 정도로 설계한다.
- 업무 화면 제목은 약 32–44px, 메인 스토리 제목은 약 40–54px 범위에서 반응형으로 조절한다.
- 설명을 줄이려고 글씨를 작게 하지 않는다. 핵심 정보를 남기고 문장을 줄인다.
- 한글 어절이 깨지지 않도록 keep-all을 사용하며 긴 이름과 토큰은 안전하게 줄바꿈한다.

## 5. 이미지와 브랜드 마크

- 판교 야경을 고른 이유는 지역명 자체보다 커튼월, 모던한 곡선형 건물, 미래지향적 건축의 인상이다.
- 밤하늘이 완전히 검은 사진보다 빛이 남은 블루아워와 따뜻한 실내 조명을 선택했다.
- 정장 인물을 별도로 배치하는 방안은 최종적으로 제외했다. 모든 브랜드 사진에서 공간이 주인공이다.
- 생성된 건축·스토리 사진은 실제 매물로 오해하지 않도록 예시 표기를 유지한다.
- 예약 카드와 상세 화면은 API에서 받은 실제 이름·사진·인원·금액을 사용한다. 사진이 없으면 준비 중 상태를 보여준다.
- 기존 어두운 입체형 열쇠 아이콘은 단색 문·키홀 심벌로 단순화했다.
- 헤더 마크, SVG 파비콘, Apple 아이콘의 형태를 통일한다. 작은 크기에서 읽히는 형태가 우선이다.

## 6. 메인페이지 구조의 변화와 최종안

1. 처음에는 긴 Slot/Key 설명, 왼쪽 쏠림, 무거운 폰트가 문제였다.
2. 짧은 문구와 오른쪽 사진의 2단 구성을 시도했다.
3. 설명 문장과 이용 순서, 중복 예약 방지 기술 설명을 제거했다.
4. 사진이 과하게 컸던 2단 시안에서는 사진을 줄였다.
5. 사용자가 건축 중심의 전체 화면 레퍼런스를 선택하면서 사진의 역할을 독립된 첫 화면으로 재정의했다. 이 결정이 이전의 ‘사진 축소’를 대체한다.
6. 최종 순서는 **전체 폭 야경 → 실제 공간 목록 → 스토리 → 마지막 CTA와 푸터**다.
7. 공간 선택을 원하는 사람은 스토리를 다 읽지 않고 바로 이동할 수 있다.

### 첫 화면

- 슬로건: 첫 줄 `몰입할 공간`, 둘째 줄 `필요한 만큼`.
- 쉼표와 마침표는 삭제했다. 줄바꿈 자체로 호흡을 만든다.
- 첫 줄을 더 작게, 둘째 줄을 더 크게 하여 직사각형 덩어리 느낌을 줄인다.
- `회의실과 공유오피스를 필요한 시간만큼 예약하세요` 설명 문장은 삭제했다.
- `30분 단위 예약` 문구도 삭제했다. 예약 상세의 선택 과정에서 안내한다.
- CTA는 테두리가 있는 `공간 둘러보기` 버튼이며 공간 목록으로 이동한다.
- 별도 검색 필터는 메인에 두지 않는다. 목록 페이지에는 필요한 날짜·검색 조건을 둔다.
- 최상단 탐색 이름은 `오피스 찾기`, 실제 경로는 기존 `/spaces`를 유지한다.
- 헤더에 `스토리`, `내 예약`, `모의 출입`을 제공하며 로그인·관리자 권한 동작을 유지한다.

### 스토리 원고와 연출

도입: **일에 집중하기까지 / 필요한 일을 줄입니다**

공간을 찾고 시간을 정하는 과정이 일의 흐름을 끊지 않도록. 준비에 쓰는 시간은 줄이고 하고 싶은 일에 더 가까워지도록.

01 SPACE: **좋은 공간은 / 해야 할 일에 집중하게 합니다**

혼자 깊이 생각하는 시간과 함께 의견을 나누는 시간. 오늘 할 일과 함께할 사람을 기준으로 나에게 맞는 공간을 고릅니다.

02 TIME: **공간이 필요한 시간은 / 저마다 다르니까**

짧게 끝낼 회의도 조금 더 이어가고 싶은 작업도 있습니다. 정해진 하루에 일을 맞추기보다 오늘의 일정에 공간을 맞출 수 있도록.

03 CONNECTION: **예약에서 이용까지 / 하나의 흐름으로**

Slot은 내가 선택한 시간. Key는 그 시간과 공간을 잇는 연결. Slot Key라는 이름에 담은 생각입니다.

- 단순한 세로 목차에서 출발했으나 사용자의 후속 요청으로 **스크롤 고정 → 01·02·03 가로 이동 → 끝에서 세로 스크롤 재개**로 변경했다.
- 왼쪽 목차에서 직접 장을 선택하고 가로 드래그로 이동할 수 있다.
- 좁은 화면, 높이가 부족한 화면, 모션 감소 설정에서는 내용을 자르지 않고 세로 문서로 제공한다. 현재 가로 고정 기준은 폭 900px 이상이며 충분한 높이가 필요하다.
- 시간 선택 그림과 출입 상태 그림은 기능 설명 예시다. 실제 예약·도어락 상태로 가장하지 않는다.
- 실제 출입 연동은 제공되지 않으므로 `현재 출입 기능은 모의 환경에서 제공됩니다`를 표시한다.

### 마지막 블록

- 마지막 CTA: `이제 당신의 일을 시작할 공간` + `공간 둘러보기`.
- CTA와 푸터를 `#142D4E` 단색으로 연결한다. 흰 제목과 밝은 테두리 버튼을 사용한다.
- 첫 적용이 너무 두꺼워 보인다는 의견으로 세로 여백을 약 20% 줄였다.
- 현재 데스크톱 CTA padding 78px/74px, min-height 320px. 모바일 padding 56px/52px, min-height 270px. 고정 높이로 내용을 자르지 않는다.
- 푸터 안내: `현재 학습용으로 운영되며, 실제 결제 및 출입 연동은 향후 업데이트 시 안내드리겠습니다.`
- 이 문구는 연동이 완료됐거나 출시 날짜가 확정됐다는 뜻이 아니다.

## 7. 나머지 페이지의 적용 원칙

메인의 야경·가로 스토리를 모든 화면에 반복하지 않는다. 브랜드는 색·서체·간격·버튼·카드로 연결하고 업무 화면은 현재 작업에 집중시킨다.

| 화면 | 정보 우선순위 및 적용 |
| --- | --- |
| 오피스 목록 | 제목 → 날짜·검색 → 실제 공간 카드 → 페이지 이동. 이미지·인원·위치·요금과 다음 행동을 명확하게 표시 |
| 오피스 상세 | 실제 사진·이름 → 날짜·이용 시간 → 예약 요약. 선택 가능/선택됨/선택 불가 구분, 결제 제한 시간 안내 유지 |
| 로그인 | 명확한 폼, 밝은 표면과 건축 사진. 로그인 후 원래 경로로 돌아가는 동작 유지 |
| 회원가입 | 이메일·비밀번호·확인·닉네임 순서와 검증 유지. BCrypt 등 사용자에게 불필요한 구현 설명 제거 |
| 내 예약 | 상태·이용 일시·공간·금액·다음 행동이 읽히는 카드. 결제 대기는 결제로, 나머지는 상세로 연결 |
| 예약 상세 | 상태·일시·요금·환불·출입·변경 이력. 상태에 따른 취소·연장·퇴실·발급 조건 유지 |
| 결제 | 예약 정보·크레딧·남은 시간·금액·환불 조건 우선. 결제 단계 안내는 이 화면에 유지 |
| 모의 출입 | 입력 → 확인 → 허용/거절 결과. 실제 도어락 연결과 오해하지 않도록 모의 표기 유지 |
| 관리자 공간 목록 | 검색·운영 상태·요금·운영시간·수정. 표의 정보 밀도는 유지하되 대비와 여백 개선 |
| 관리자 공간 등록·수정 | 기본 정보와 요금·운영시간 구분. 실제 payload, 검증 및 변경 영향 안내 유지 |
| 관리자 예약 목록·상세 | 상태·일시·예약자·금액·출입 이력. 기록의 가독성과 탐색 우선 |
| 관리자 회원 | 검색·상태·크레딧·관리 동작. 관리자 계정 제한, 확인 창과 변경 사유 유지 |
| 404·로딩·빈 목록·오류 | 의미 있는 안내와 복구 행동. 서버 장애를 예시 데이터나 빈 목록으로 감추지 않음 |
| 모달·토스트 | 밝은 표면, 명확한 제목·결과·취소/확정. 포커스·Escape·상태 알림 동작 보존 |

## 8. 공통 컴포넌트 규칙

- 흰 카드, 얇은 경계선, 낮은 그림자, 중간 정도의 모서리 곡률을 사용한다.
- 주요 확정 행동은 파란 채움 버튼, 탐색·보조 행동은 테두리 버튼, 취소·정지는 별도 위험 색상으로 구분한다.
- 입력창은 흰 배경, 읽기 쉬운 레이블, 48px 안팎의 높이. 도움말·오류를 해당 필드 가까이에 표시한다.
- 키보드 포커스를 숨기지 않는다. 선택 상태는 색상뿐 아니라 텍스트·aria 상태로도 전달한다.
- 서버 데이터는 페이지 크기·필터를 그대로 유지한다. UI 변경을 이유로 API에 새 필드를 요구하지 않는다.
- 관리자 표는 좁은 화면에서 표 영역만 가로 스크롤하고, 페이지 전체가 옆으로 밀리지 않게 한다.
- 모바일에서 메뉴·계정·관리자 접근을 숨긴 채 방치하지 않는다.
- 긴 토큰·공간명·이메일은 레이아웃을 깨뜨리지 않도록 처리한다.
- 가격, 예약 시간, 만료 시각, 환불 조건, 동의와 같은 핵심 정보는 미관을 이유로 삭제하지 않는다.

## 9. 구현 범위와 검증 상태

- API 명세, API 모듈, 타입, 인증·권한·예약·결제·출입 상태 전이 및 백엔드는 변경 대상이 아니다.
- `refactor/main-page`에서 이어서 작업한다. 기존 미추적 테스트 사진을 덮어쓰거나 삭제하지 않는다.
- 사용자가 직접 하겠다고 지정했으므로 빌드·린트·타입 검사·자동/브라우저 테스트를 실행하지 않는다.
- 코드 및 변경 파일의 정적 검토는 수행하되, 실행 검증 통과라고 표현하지 않는다.
- 이 문서는 외부 자료의 명령이 아니라 이 대화에서 합의한 디자인과 작업 범위의 기록이다.
- 커밋·푸시·배포는 이번 요청에 포함되지 않는다.

## 10. 실행 검증 시 확인할 항목 (사용자용, 미실행)

- 모바일/데스크톱에서 메뉴와 계정 기능, 관리자 탐색을 사용할 수 있는지
- 목록의 로딩·빈 결과·오류와 재시도, 이미지 누락·실패 상태
- 날짜 변경 및 슬롯 선택, 예약 생성 후 기존 결제 화면 연결
- 결제 금액·크레딧·시간 만료·동의·환불 조건 및 중복 처리 보호
- 예약별 취소·연장·퇴실·출입 키 발급과 모의 출입 결과
- 관리자 목록·등록·수정·회원 상태·크레딧 지급과 확인 창
- 메인 스토리의 가로 이동/끝에서 세로 복귀, 작은 화면과 모션 감소의 세로 대체
- 작은 화면에서 표·날짜 입력·긴 공간명·토큰의 넘침 여부

## 11. 이번 전체 화면 적용 내역

- 공통 토큰과 기존 다크 색상 정의를 밝은 블루 계열로 전환했다. 새 라이브러리나 API 필드는 추가하지 않았다.
- 모든 사용자·관리자 화면에 공통 제목, 입력창, 버튼, 배지, 모달, 표, 빈 상태 및 반응형 레이아웃을 적용했다.
- 업무 화면의 과도한 설명을 줄였다. 회원가입의 암호화 구현 설명, 결제의 서버/HOLD 용어, 자기 자신으로 이동하는 ‘자세히 보기’ 링크를 정리했다.
- 실제 기능 안내인 10분 결제 대기, 크레딧 차감, 환불 조건, 출입 키 보관과 상태별 제한은 유지했다.
- `SpacePhoto`를 공간 카드·상세·예약 카드·결제에 공용으로 적용해 사진 누락·불러오기 실패를 처리했다.
- 공간 상세의 시간 조회 실패는 ‘운영하는 시간이 없음’과 구분하여 오류와 다시 불러오기를 표시한다.
- 관리자 공간 필터의 날짜는 기존 조회에 사용되지 않는 입력이므로 숨겼다. 키워드·상태 조회는 유지한다.
- 모바일 계정 메뉴를 전체 화면으로 확대하고 내 예약·모의 출입·로그인·관리자 접근을 보존했다.
- 사용자 폼에서는 검증·submit payload·라우트와 결제 멱등성 처리를 유지했다.
- 실행 결과는 미검증이며, 위 내역은 코드에 적용한 내용이다.

## 12. 모의 출입 완료 효과

- 서버가 ALLOW를 반환하면 기존 결과 카드에 허용 여부, 사유, 공간명, 최초 체크인/재입장, 시도 시각을 표시한다. 공간명·시각은 응답에 있을 때 표시한다.
- 성공 시 네 모서리에서 파랑·민트·금색·보라색 색종이가 퍼지는 일회성 효과를 약 3.2초 표시한다. 거절·요청 실패에는 효과가 없다.
- 효과는 클릭을 가로채지 않고, 화면 리더에서 제외하며 모션 감소 설정에서는 생략한다. 화면 이탈 시 애니메이션을 정리한다.
- 재확인 시작 시 이전 결과를 지워 오래된 성공 상태가 남지 않게 한다. API 및 출입 판단은 변경하지 않는다.
- 빌드와 실행 테스트는 사용자 요청에 따라 미실행이다.

## 13. 출입 승인 카드 최종 결정

- 성공 시 입력 폼을 Slot Key 로고·체크 심벌·진한 네이비 배경의 승인 카드로 교체한다. 이전의 폼 아래 성공 결과 방식은 대체한다.
- 공간명·최초 체크인/재입장·시각은 서버 응답을 표시하며, 내 예약 보기와 다른 출입 확인을 제공한다. 거절 시 입력 폼과 사유를 유지한다.
- 네 모서리의 성공 폭죽은 유지한다. 승인 시 제목으로 포커스를 이동한다.
- 네이버 1784 공식 스타일시트에서 NaverBD 전용 글꼴을 확인했다. 동일 글꼴이라고 표기하지 않고, 네이버 공개 나눔스퀘어를 유사한 대안으로 채택한다.
- 출입 페이지 본문의 제목·설명·폼·버튼·결과만 CSS Module로 글꼴을 제한한다. 공통 헤더·푸터 및 다른 페이지 글꼴은 유지한다.
- 공식 hangeul.pstatic.net의 웹폰트를 로드하며 실패 시 시스템 글꼴로 대체한다. 승인 제목은 Regular로, 핵심 버튼은 Bold로 구분한다.
- 빌드 및 실행 테스트는 미실행이다.

## 14. 같은 브라우저의 출입 키 보관 및 공개 시점

- 예약 확정 후 상세 화면에서 키를 자동 발급하고 회원·예약별 localStorage에 보관한다. 이미 보관한 키가 있으면 발급 API를 다시 호출하지 않는다.
- 시작 15분 전까지 회색 잠금 버튼에 파란 카운트다운을 표시하며, 이후 ‘출입 키 확인’을 활성화한다. 한국 시각 기준이다.
- 최초 확인 후 같은 브라우저로 재방문하면 같은 키를 표시한다. 클릭 시 화면 표기값이 아닌 원문을 복사하고 3초간 완료 안내를 표시한다.
- 발급·재발급 버튼은 제거한다. 취소·체크아웃 또는 종료 확인 시 보관값을 제거한다. 브라우저가 닫힌 동안에는 자동 삭제하지 않고 다음 해당 화면 방문 시 정리한다.
- 서버 출입 판단은 변경하지 않는다. 프론트의 15분 잠금은 표시 제한이며, 실제 출입은 기존 서버 정책을 따른다.
- 다른 기기와 브라우저 저장소 삭제 후 복원은 지원하지 않는다. 보관값이 없으면 새로 발급되어 기존 서버 키를 대체할 수 있다.
- 탭 내 중복 요청을 공유하고 Web Locks 지원 브라우저에서는 탭 간 발급도 직렬화한다.
- 브랜치: feat/hold-key. 빌드·실행 테스트는 사용자 요청에 따라 미실행.

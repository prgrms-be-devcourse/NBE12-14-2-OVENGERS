## 서비스 개요

- 서비스명: Slot Key — "시간을 Slot으로 나누고, 예약한 Slot이 하나의 Key가 된다."
- 회의실·공유오피스를 30분 단위로 예약하고, 예약 상태·이용 시간에 맞춰 출입 권한(Mock Door)을 제공하는 서비스.
- 예약은 2단계로 처리한다: ① 슬롯 확보 시 `HOLD` 상태로 생성(결제 대기, 10분 후 자동 만료) → ② 결제 확인 페이지에서 크레딧 차감에 성공하면 `CONFIRMED`로 확정. *(2026-09-15 정정 — 기존에는 "하나의 트랜잭션으로 즉시 처리, 별도 결제 대기 상태 없음"이었으나, 결제 확인 단계를 두기로 하면서 `HOLD`가 그 대기 상태가 되었다.)*

## 해결하려는 문제 (기획서 2장)

1. **동시 예약**: 같은 공간·시간대를 두 사용자가 거의 동시에 예약하면 서버가 확실히 하나만 확정해야 한다. 화면의 예약 가능 여부는 참고용 스냅샷일 뿐, 실제 차단은 예약 생성 시점의 DB 제약으로 한다.
2. **예약 상태와 출입 권한의 불일치**: 예약 취소·이용 종료·계정 정지 이후에는 기존 출입 토큰이 남아 있어도 출입을 거절해야 한다. 출입 요청마다 회원 상태·예약 상태·허용 시간을 함께 확인한다.

이 프로젝트는 인증·인가를 "로그인 성공 여부"에서 역할 기반 인가 + 소유권 기반 인가 + 상태 기반 인가 + 시간 기반 인가로 확장하는 것을 핵심 목표로 삼는다.

## MVP 핵심 기능 (필수, 4-1)

| # | 기능 | 설명 |
| --- | --- | --- |
| 1 | 공간 예약 생성·조회·취소·연장 | 회원은 공간 상세 페이지에서 예약(HOLD)을 생성하고 결제 확인 후 확정하며, 자신의 예약을 조회·취소·연장(같은 슬롯 유지, 종료 시각만 늘림)할 수 있다. 관리자는 전체 예약·취소 이력 조회 |
| 2 | 예약 기반 출입 | 예약자·예약 상태·허용 시간을 확인해 도어 토큰 발급·검증. 최초 체크인 성공 시 이용 중 상태로 전이하며, 종료 시 체크아웃으로 마감 |
| 3 | 오피스 조회 및 관리자 운영 관리 | 관리자가 공간을 등록·관리, 회원은 등록된 공간을 조회 |

## Out of Scope (4-2, 의도적 제외)

- 소셜 로그인, 모바일 앱, 다국어 지원
- 실제 도어 하드웨어 연동 (Mock Door API로 대체), 실제 PG 결제 (크레딧 잔액 차감으로 대체 — 셀프 충전도 범위 밖)
- **예약 변경(시간대 이동)** 및 자동 재예약 보장 (취소 후 재생성만 허용). **연장(기존 슬롯 유지, 종료 시각만 늘리는 것)은 별개이며 MVP에 포함한다** — 기존 슬롯을 해제하지 않으므로 변경과 달리 실패해도 원 예약이 무손상이다. *(2026-09-15 명확화)*
- 예약 대기(대기번호)·승격, 관리자 점검 시간 블록, 셀프 크레딧 충전, 크레딧 회수, 출입 키 공유·동행자 초대, HOLD 시간의 사용자 연장(만료 시각 자체를 늘리는 것 — 예약의 "연장"과는 다른 개념) *(2026-09-15 추가, `core-domain-decisions.md` §10)*
- Refresh Token Family 전체 폐기/재사용 공격 추적, Access Token 블랙리스트 (로그아웃은 Refresh Token만 폐기, Access Token은 만료로 처리)
- 여러 요금 구간을 가로지르는 예약 (하나의 예약은 단일 요금 구간)
- 동적/피크타임 요금, 회원 등급별 차등 요금
- 공간 소유자의 개별 예약 강제 취소 (강제 취소는 PLATFORM_ADMIN 경로에서만)
- 팀 관리자의 대리 체크인·대리 취소 (예약자 본인만)
- 권한 조회용 로컬 캐시 (DB 즉시 조회)

## 성공 기준 (11장 DoD 발췌 — 전체는 README 참고)

- 동일 공간·시간에 20개 동시 예약 요청 중 정확히 1건만 성공, 실패 요청의 예약·슬롯 데이터는 남지 않는다.
- 같은 Idempotency-Key로 결제 요청을 3회 중복 제출해도 크레딧 차감·예약 확정은 한 번만 처리된다.
- 예약 취소 직후 기존 도어 토큰 검증은 실패한다.
- 계정 정지 후 같은 Access Token으로 요청해도 보호된 기능은 거절된다.
- 공간 요금이 변경돼도 기존 예약 금액은 유지되고, 새 예약에만 변경된 요금이 적용된다.
- 임의 시점에 `SUM(credit_transaction.amount) == member.balance`가 항상 성립한다. *(2026-09-15 추가)*
- 시작+15분까지 미체크인이면 노쇼로 전이되고 슬롯은 반환되지만 환불은 없다. *(2026-09-15 추가)*
- `HOLD` 상태에서 결제 확인 페이지에 머무는 동안 관리자가 가격을 바꿔도, 결제 시 `space.version` 불일치로 거절된다(가격이 아니라 버전으로 비교). *(2026-09-15 추가)*

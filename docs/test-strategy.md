# 테스트 전략

> 출처: `docs/core-domain-decisions.md` §12(테스트 목록). 이 문서는 그 목록을 실행 가능한 테스트 전략으로 정리한 것이다.
> **원칙: 문서에 적은 규칙은 전부 테스트로 존재해야 한다. 규칙 하나 = 테스트 하나.** 새 규칙이 core-domain-decisions.md에 추가되면 이 문서에도 대응하는 항목을 추가한다.

## 도구

- **Testcontainers(MySQL)**: 실제 MySQL을 띄워 UNIQUE 제약·조건부 UPDATE·트랜잭션 동시성을 검증한다. H2 등 인메모리 DB로는 락/제약 동작이 실제와 달라질 수 있어 사용하지 않는다.
- **`Clock` 주입**: 시간 경계 테스트는 실제로 대기하지 않고 고정 시각을 주입해 검증한다(`HELD` 만료, 체크인 경계, 노쇼 판정 등).
- **다중 스레드/커넥션**: 동시성 테스트는 여러 스레드에서 동시에 같은 API를 호출해 재현한다.

## 1. 동시성

| # | 시나리오 | 기대 결과 |
| --- | --- | --- |
| 1-1 | 같은 슬롯에 20개 동시 예약 요청 | 정확히 1건 성공(HOLD), 19건 409. 실패 요청의 예약·슬롯 데이터 잔존 없음 |
| 1-2 | 만료된 HELD가 있는 슬롯에 신규 예약 요청 (배치 미실행 상태) | 성공 — 예약 생성 시점의 조건부 UPDATE+삭제가 만료 정리를 보장하므로 배치 실행 여부와 무관 |
| 1-3 | 같은 `Idempotency-Key`로 결제(`/pay`) 3회 요청 | 크레딧 차감은 1회만 발생, 3번의 응답이 동일 |
| 1-4 | 연장 ↔ 신규 예약 동시 요청(같은 슬롯) | 둘 중 먼저 커밋한 쪽만 성공, 나머지 409 |
| 1-5 | 같은 예약에 연장 요청 2회 동시 제출 | `end_time` 낙관적 검사로 하나만 성공 |

## 2. 크레딧

| # | 시나리오 | 기대 결과 |

## 3. 상태 전이

| # | 시나리오 | 기대 결과 |
| --- | --- | --- |
| 3-1 | 허용되지 않는 전이 6종 각각 시도: `EXPIRED→*`, `CANCELLED→*`, `COMPLETED→*`, `HELD→IN_USE`, `NO_SHOW→IN_USE`, `IN_USE→CANCELLED` | 전부 거절 |
| 3-2 | `HELD` 상태에서 도어 토큰 발급 시도 | 거절(`RESERVATION_NOT_CONFIRMED`) — 결제 없이 입장 불가 |
| 3-3 | 취소 후 같은 예약을 재취소 시도 | 409 |
| 3-4 | 시작 이후 취소 시도(체크인 여부 무관) | 거절 — 시작 이후는 체크아웃으로만 종료 |
| 3-5 | 시작 + 15분까지 미체크인 | 배치가 `NO_SHOW`로 전이, 슬롯 전부 삭제, 환불 없음 |
| 3-6 | 종료 시각 경과 후 미체크아웃(`IN_USE`) | 배치가 자동 `COMPLETED` 전이, `checked_out_at` = `end_time`(배치 실행 시각이 아님) |

## 5. 인가

| # | 시나리오 | 기대 결과 |
| --- | --- | --- |
| 5-1 | 일반 회원이 타인 예약 조회·취소·도어 토큰 발급 시도 | 전부 거절 |
| 5-2 | **관리자**가 타인 예약 취소·도어 토큰 발급 시도(force-cancel 경로 아님) | 거절 — 관리자 권한은 소유권 검사를 대체하지 않음 |
| 5-3 | 일반 회원이 크레딧 지급 API(`/admin/members/{id}/credits`) 호출 | 거절(`FORBIDDEN_ROLE`) |
| 5-4 | 관리자가 자기 자신에게 크레딧 지급 시도 | 거절(`SELF_GRANT_NOT_ALLOWED`) |
| 5-5 | 정지된 계정이 만료 전 기존 Access Token으로 보호 API 요청 | 허용 — Access JWT 클레임으로 인증하며 회원 DB를 재조회하지 않음(`AuthControllerTest#t15`) |
| 5-6 | 정지된 계정이 리프레시 토큰으로 재발급(`/auth/refresh`) 시도 | 거절(`ACCOUNT_INACTIVE`, 403) — refresh 시점에 회원 상태를 DB에서 검증함(`AuthControllerTest#t15`) |

## 남은 논의

노쇼 환불률은 현재 0%로 확정했으나 강사 피드백에 따라 재검토 중이다(`core-domain-decisions.md` §13). 값이 바뀌면 2-4, 3-5 항목의 기대 결과와 이 문서를 함께 갱신한다.

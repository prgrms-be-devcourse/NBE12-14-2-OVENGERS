# 알림 목록과 일괄 읽음 처리

## 한 줄 요약

기존 알림 조회에 목록 화면과 본인 알림 일괄 읽음만 추가한다.

## 1. 문제와 배경

DB에 저장된 알림을 사용자가 볼 화면이 없고 읽음 API가 없어 배지가 줄지 않는다. 기존 예약·인증·이벤트 전달 흐름은 유지한다.

## 2. 선택과 이유

토큰 회원 id와 read_at IS NULL을 조건으로 단일 UPDATE하고 updatedCount를 반환한다. 프런트는 최초 목록 표시 후 호출하며 스냅샷을 유지한다. 세부 결정은 [자율 결정 기록](../lab/notes/waitlist-outbox/step-ui.md)에 둔다.

## 3. 기각한 대안과 이유

| 대안 | 장점 | 기각한 이유 |
| --- | --- | --- |
| 항목마다 읽음 API | 개별 제어 | 최소 읽음 요구보다 복잡하고 요청 수 증가 |
| 목록 조회 전에 읽음 처리 | 구현 간단 | 처음부터 안 읽은 표시가 사라짐 |
| 주기적 폴링 | 새 알림 반영 빠름 | 명시된 범위 밖, 불필요한 주기 요청 |

## 4. Trade-off

| 얻는 것 | 잃는 것(비용·위험) | 완화책 |
| --- | --- | --- |
| 단일 UPDATE와 간단한 UX | 다른 페이지의 알림도 읽음, 조회 직후 도착한 알림도 포함 가능 | 일괄 읽음 의미를 명시하고 배지는 서버 개수 재조회 |
| 최초 안 읽음 표시 유지 | 읽음 후 현재 화면은 스냅샷 | 다음 목록 조회부터 반영 |

## 5. 검증

### 검증 계획

본인만 읽음·기존 읽음 시각 유지·재요청 0건·무토큰 401 통합 테스트. API 경로·파라미터·매핑·배지 조건 프런트 테스트. 전체 테스트, lint, build와 가능한 로컬 브라우저 검증.

### 검증 결과

자기검증(복구 세션): ./gradlew test --rerun-tasks 성공. {'tests': 816, 'failures': 0, 'errors': 0, 'skipped': 11}. 프런트 node --test tests/*.test.cjs 54/54 통과, npm run lint 오류 0·기존 경고 7, npm run build 성공, git diff --check 통과. 브라우저 수동 검증과 CI는 미실행.

## 6. 한계와 재검토 조건

실시간 전달 및 개별 읽음은 제외한다. 요구가 생기면 별도 설계한다. 동시 도착 알림도 일괄 읽음 시점 기준으로 처리한다.

## 면접·발표용 정리 (구현 후)

회원 id와 미읽음 조건을 단일 UPDATE에 포함해 타인 알림과 기존 읽음 시각을 보존했다. UI는 목록 스냅샷을 유지하고 서버의 안 읽은 개수를 재조회한다. 일괄 처리에는 다른 페이지와 동시 도착 알림도 포함되는 trade-off가 있다.
